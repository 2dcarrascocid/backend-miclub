Explica código o conceptos de forma clara y directa.

## Qué Explicar
$ARGUMENTS

---

## Proceso

1. Lee el código o archivo mencionado antes de explicar
2. Identifica el nivel de detalle apropiado según el contexto
3. Explica de lo general a lo específico

---

## Estilo de Explicación

- **Sin jerga innecesaria** — si usas un término técnico, defínelo brevemente
- **Ejemplos concretos** — muestra el código en acción, no solo en abstracto
- **El "por qué" importa** — no solo qué hace el código, sino por qué está hecho así
- **Flujo completo** — si es un endpoint, explica el viaje desde el request hasta el response
- **Conectar con el proyecto** — relacionar con el stack real (Lambda, Supabase, Vue, etc.)

---

## Formatos según el tipo de consulta

### Para un archivo o función
```
## ¿Qué hace {nombre}?
{resumen en 1-2 oraciones}

## Flujo paso a paso
1. ...
2. ...

## Puntos clave
- {algo no obvio o importante de entender}

## Ejemplo de uso
{código de ejemplo si aplica}
```

### Para un concepto técnico
```
## {Concepto} en palabras simples
{analogía o explicación directa}

## Cómo aplica en este proyecto
{ejemplo específico del codebase}

## Qué tener en cuenta
{gotchas o cosas a no confundir}
```

### Para un error o comportamiento
```
## Por qué ocurre esto
{causa raíz explicada}

## Qué está pasando internamente
{mecanismo detrás del comportamiento}

## Cómo evitarlo o manejarlo
{patrón correcto}
```
